# 0043. Resilience of the decentralised optimiser: link failures, offline agents, and detect-and-isolate for a misbehaving agent

Status: **Proposed (implementation; experiment 021 decides)**   Date: 2026-11-08   Where: `graph_admm.py` (`link_fail`, `faulty`, `attack`, `trim`, `detect`, `wmsr_mix`, `extreme_share`, `solve_cells_resilient`, `subproblem`, topology `ring2`), `engine.py`, `config.py`, `run_benchmark.py`   Evidence: tests in `tests/test_graph_admm.py`; experiment 021

## Context
The proposal promises a *resilient* decentralised consensus: the system should keep working when links fail, when an agent drops out, and when an agent misbehaves, and it names W-MSR (the lecture's trimmed-mean resilient consensus). Decision 0042 built the neighbours-only optimiser (sharing ADMM with dynamic average consensus) and said the resilient mixing step would go into its mixing step. Its correctness rests on one invariant: the agents' estimates of the average position always sum to the true sum of positions, which holds because the mixing matrix is doubly stochastic.

## Options and what the prototype showed (development problems, seeds 0-2, eight agents; not part of experiment 021)
1. **Link failures**: every edge is down with probability q in every gossip round, and the Metropolis weights are recomputed on the edges that are up. The mixing stays doubly stochastic, so the invariant holds and the solver still reaches the optimum. Prototype: q = 0.3 converged on the complete graph and the ring, with up to 1.7 times the iterations.
2. **An offline agent**: the agent's positions are closed and the others solve the problem without it, on the graph without its node (on a ring, a line). No new mathematics: it is the same solver on fewer agents. The hub can do the same; the difference is that a hub is a single point of failure (if the hub is down nobody can trade), which is not simulated.
3. **W-MSR trimmed mixing inside the ADMM** (the lecture's algorithm, F = 1): each agent ignores, coordinate by coordinate, the largest neighbour value above its own and the smallest below it. Prototype: **it breaks the optimiser even with no attacker** (net-position error 40-120%, no convergence), because trimming throws away part of the estimates' sum, so the invariant is lost and the agents agree on a wrong average. With a liar it did not help either (error 3-5 times a typical position). This matches the literature on resilient distributed optimisation: trimming gives robustness at the cost of exactness.
4. **Detect and isolate** (chosen for the misbehaving agent). The W-MSR test is kept as a DETECTOR, not as a mixing rule: agent i notes, every iteration, the share of coordinates in which neighbour j sent the most extreme value beyond i's own (the value W-MSR would discard first), for both the average estimates and the prices. A neighbour that is extreme in at least 90% of coordinates of both for 50 iterations in a row is flagged; an agent flagged by more than half of its neighbours is isolated, and the others restart on the graph without it (option 2). Plain mixing is used otherwise, so with no attacker the solver is exactly decision 0042's. Prototype: on the complete graph a liar adding a constant to everything it sends was isolated at every size tried (0.001 to 1.0, i.e. from 4% of a typical position), no honest agent was ever isolated, and the result was the optimum without the liar. On the plain ring (two neighbours per agent) honest agents were isolated too and the graph fell apart, as the lecture's robustness condition predicts (W-MSR with F = 1 needs a (2, 2)-robust graph; a ring is not). On `ring2` (each agent linked to the two nearest on each side: sparse, but robust) it worked like the complete graph. A liar that sends random noise was isolated in one of three problems; in the other two the result was badly wrong (net error 12-15 times a typical position): **detect-and-isolate does not stop a liar who hides inside the honest range.**

## Decision
Options 1, 2 and 4, behind configuration flags that are off by default (`link_fail = 0`, `offline = ()`, `faulty = ()`, `detect = 0`), so every earlier result is unchanged. Option 3 (`trim`, `wmsr_mix`) is kept only until experiment 021 has recorded its failure on fresh problems; if A5 there confirms it, it is deleted (rule: rejected code is deleted).
- A faulty agent in the simulation holds nothing (so the right answer is known: the optimum without it). In hub mode a faulty agent is simply left out (a hub has no messages to corrupt).
- An agent isolated by the detector stays out for the rest of the run (quarantine).
- Parameters (90% of coordinates, 50 iterations, majority of neighbours) were set on the development problems before experiment 021 and are not tuned on it.

## Consequences
- The proposal's resilience claim can be stated precisely: link failures and offline agents cost only extra communication; a consistent liar is caught on a robust graph; a stealthy liar is not, and a sparse graph that is not robust (the ring) cannot be protected this way.
- The stealthy liar points at the safety supervisor (Step 4, STL): a solve that does not converge should not be traded.
- Detection adds work per iteration (each agent compares its neighbours' values) and the restarts add iterations.
- What is still central in the simulation: the decision to restart is applied to everyone at once (a deployment would flood the isolation over the graph, taking at most its diameter in rounds).

## Rollback
Leave the flags at their defaults (nothing changes), or delete the options from `graph_admm.py`, `engine.py`, `config.py` and `run_benchmark.py` and the resilience tests; decision 0042's solver is untouched by them when the flags are off.
